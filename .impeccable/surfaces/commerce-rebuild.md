# Commerce replacement

The user requested replacement of Branches, Catalog, Orders and Reports, a fresh ecommerce setup with Meta two-way catalog sync and WhatsApp payments, and explicitly authorized permanent deletion of existing local commerce data for **all companies**. Country/provider: India/Razorpay. Do not delete CRM contacts, conversations, companies, API connections or remote Meta catalogs.

The incumbent teal MUI design and authenticated app shell remain authoritative. New commerce routes provide Setup, Products, Locations, Orders, Payments and Reports. The four old page implementations are replaced. Reusable product/category/variant/add-on/inventory/location/delivery/order editors remain available through the new screens, with their old purple accents replaced by teal. Mobile records stack instead of hiding actions in wide tables.

Company-specific commerce settings hold a selected WhatsApp account, catalog ID, five-minute automatic sync setting, payment configuration and encrypted Razorpay credentials. Credentials never return in API responses. Catalog jobs pull real Meta records, submit local changes as pending, confirm via remote readback, flag concurrent edits and reconcile deletions. Missing connections never produce simulated success. The old fake catalog service is removed. Sync covers the product description, primary image, product URL, identifiers, effective price and availability; it does not claim bidirectional branch-level inventory quantities or variants.

Native WhatsApp catalog carts use current store prices. Checkout rechecks product availability/price, reserves tracked inventory atomically, avoids duplicate finalization, and cancellation releases stock once. Locations with order history cannot be deleted. Native Razorpay order-details messages use stable references, persist in the inbox and support manual verification. Meta payment notifications and signed company-specific Razorpay webhooks trigger provider lookups. Money is marked received only after matching reference, INR amount and currency; paid status never regresses. Scheduled lookups reconcile pending payments. Failed/ambiguous sends remain visible; live account activation and a real end-to-end checkout still require the company's own Meta/Razorpay accounts.

The reset is an explicit Artisan command, not a destructive migration: `commerce:reset --all-companies --confirm=DELETE-ALL-COMMERCE`. Run a dry run first and pause incoming/queued commerce work during execution. It removes local order sessions, payments, orders/items, inventory, branch pricing/availability, products/variants/categories/add-ons, delivery zones, branches, commerce settings and company-owned status configuration. System business types and default statuses remain.

Verification artifacts are in `.impeccable/review/commerce-*`. Browser review uses local fixture API responses only; it never sends customer messages or charges real money. Setup/save/check, sync and conflict actions, create dialog, payment requests, receipt verification, error recovery and six surfaces at 390/1440/1728 are exercised. Better Design comprehension and rendered spacing reviews cover the replacement screens. Final test and deployment results must be read from their logs; live payment processing is not claimed without account-backed verification.
